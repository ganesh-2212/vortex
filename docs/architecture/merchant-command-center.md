# F16: Merchant Revenue Command Center

The Merchant Revenue Command Center is a business-facing aggregation and visualization layer over the core Revenue Sentinel capabilities (F01–F15).

## Purpose
To provide merchants and operators with a real-time view of revenue risk, recovery performance, and active recovery operations. It synthesizes complex intelligence into actionable business metrics.

## Architecture
F16 strictly operates as a **read-only presentation layer**.

It aggregates data by consuming the outputs of existing deterministic services:
- **F10 (Guardrails)**: Authoritative safety boundaries determining blocked/allowed actions.
- **F11 (Strategy Optimization)**: Authoritative baseline strategy recommendations.
- **F12 (Simulation)**: Authoritative source for projected incremental value.
- **F13 (Orchestration)**: Authoritative decision engine for queue sorting and human escalation.
- **F14 (Historical Outcomes)**: Authoritative source for strategy performance data.
- **F15 (Explainability)**: Authoritative engine for decision evidence (linked from F16).

F16 adheres to strict boundaries:
- **No mutations**: It never modifies the `MemoryStore`, case state, merchant config, or executes actions.
- **No duplicate logic**: It relies exclusively on existing modules to perform safety checks, simulations, or orchestrations.
- **Deterministic**: Calling the command center API repeatedly without intermediate events yields identical results.

## Data Sources & Metric Definitions

### 1. Executive Revenue Metrics
- **Actual Revenue At Risk**: Sum of `amount_at_risk` across all cases.
- **Actual Recoverable**: Sum of `amount_at_risk - recovered_amount` for `OPEN`, `IN_PROGRESS`, and `ESCALATED` cases.
- **Actual Confirmed Recovered**: Sum of `recovered_amount` across `RECOVERED` cases.
- **Projected Incremental**: Re-uses the F12 Simulation `incremental_recovery_vs_basic_retry` metric.
- **Actual Recovery Rate**: `(Total Confirmed Recovered / Total Revenue At Risk) * 100`

### 2. Recovery Performance Comparison
Clearly distinguishes between actual production data and simulated outcomes.
Retrieves the latest available simulation (`store.latest_simulation`) generated by F12.
If no simulation exists, this section displays a professional empty state prompting the merchant to run one. Simulated outcomes are never silently generated during the F16 read operation to preserve determinism and read-only constraints.

### 3. Active Recovery Queue
A priority-sorted list of active cases (`OPEN`, `IN_PROGRESS`, `ESCALATED`).
Priority Ordering:
1. `CRITICAL` risk (Priority 10)
2. `HIGH` risk (Priority 20)
3. Requires human escalation (Priority 30)
4. High value (>= 10000) (Priority 40)
5. Standard (Priority 50)

### 4. Human Attention
Extracts active cases where:
- Orchestration requires human escalation (`human_escalation_required == True`)
- Case is already in `ESCALATED` status.

### 5. Strategy Performance
Integrates F14 (`get_strategy_performance()`). If insufficient data exists, handles it gracefully with empty states.

## Known Limitations
- F16 relies heavily on F12 for simulation-based incremental metrics. If a simulation has never been run, incremental revenue will not be available.
- Trend graphs are highly simplified due to the in-memory, transient nature of the test store. Real deployments would aggregate time-series data daily.
