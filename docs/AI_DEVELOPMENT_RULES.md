# AI Development Rules

VORTEX is developed with the assistance of AI coding agents. These rules define the engineering, safety, and verification boundaries that AI agents must follow when modifying the system.

## Rules

1. **Implement only the assigned milestone.**  
   AI agents must limit changes to the explicitly assigned feature or milestone.

2. **Inspect before modifying.**  
   Agents must understand the existing architecture, implementation, dependencies, and related tests before making changes.

3. **Protect unrelated functionality.**  
   Agents must not rewrite, refactor, or modify unrelated modules unless the assigned milestone explicitly requires it.

4. **Preserve API contracts.**  
   Existing API contracts, request/response schemas, and integration behavior must not be changed without explicit approval.

5. **Never introduce secrets.**  
   API keys, credentials, webhook secrets, tokens, passwords, or other sensitive values must never be committed to the repository.

6. **Test before claiming completion.**  
   Agents must not claim a milestone is complete without providing test or validation evidence.

7. **AI recommendations are not execution authority.**  
   AI-generated diagnoses and recommendations must pass through deterministic business rules and guardrails before any executable action is permitted.

8. **Financial calculations must be deterministic.**  
   Revenue, recovery amounts, costs, percentages, and other financial metrics must be calculated by deterministic application logic rather than generated by an AI model.

9. **Validate AI output.**  
   AI-generated responses must be constrained to the expected schema and validated before being consumed by downstream application logic.

10. **Every intervention must have explicit boundaries.**  
    Recovery actions must respect defined limits such as permitted action types, retry limits, case states, and stopping conditions.

11. **Every intervention must be auditable.**  
    Recovery decisions and executable actions must produce an auditable record describing what happened and the relevant decision context.

12. **Every milestone requires verification evidence.**  
    Each development milestone must include appropriate automated tests, build validation, or integration evidence.

13. **Do not fake external integrations.**  
    External payment and webhook integrations must not be represented as successful unless the corresponding integration evidence exists.

14. **Do not perform uncontrolled real-money operations.**  
    Financial integrations must remain within explicitly controlled and authorized environments. VORTEX demonstrations use Razorpay Test Mode.

15. **Git history must represent genuine development.**  
    Commits must correspond to actual development milestones, fixes, documentation, or validation work and must not be fabricated to simulate development history.

## Core Principle

> **AI may reason, recommend, and explain. Deterministic systems control execution, financial calculations, and safety boundaries. External payment evidence determines whether recovery actually occurred.**
